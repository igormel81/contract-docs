# Облачные провайдеры модели: OpenAI, DeepSeek, Kimi, Anthropic

> **Status:** in progress — модули реализованы и покрыты mock-тестами, реальное подключение не испытано.
> **Owner:** координатор.
> **Surface:** server/cloud-runner.mjs, server/model-providers/openai-compatible.mjs, server/model-providers/anthropic.mjs, server/main.mjs, test/.
> **Updated:** 2026-09-22. **Baseline:** `acc7fd1`; кандидат выпущен в составе 0.3.4. Исполнитель описывает себя через `runner.capabilities()`: вход Codex и поиск по ИНН в облачном режиме недоступны, интерфейс называет активного вендора.

## Что считаем результатом

Codex остаётся базовым режимом (см. [план локальной установки](<(sep-26)-local-installation.md>), LOC-01…04). Облачный вендор — ещё один явный выбор администратора на уровне процесса, наравне с локальной моделью: один провайдер на запущенный инстанс, фиксируется при старте через `DOCS_MODEL_PROVIDER`, переключение на живом инстансе не поддерживается. Никакого скрытого fallback между провайдерами.

Все четыре вендора реализованы одновременно: OpenAI/DeepSeek/Kimi через общий `OpenAICompatibleProvider` (параметризован `vendor`/`baseUrl`/`structuredOutputMode`), Claude — через отдельный `AnthropicProvider` (Messages API, `x-api-key`, structured output через `output_config.format`, не `tool_use`). `CloudRunner` — общий раннер для всех четырёх, аналог `LocalRunner`, но без привязки к ревизии модели/токенизатора/шаблона (эти вендоры не отдают такие данные — закрепляются только `provider` и `model`).

## Ключевые архитектурные решения

- **Структурированный вывод.** OpenAI и Kimi поддерживают `response_format:{type:"json_schema",strict:true}` — точное соответствие схеме на стороне вендора. DeepSeek — только `response_format:{type:"json_object"}` (свободный JSON, без серверной проверки схемы). Anthropic использует отдельное поле `output_config.format.schema`, которое не поддерживает `minLength`/`maxLength`/`pattern`/`$ref` — исходящая схема проходит через `sanitizeSchema()` в `anthropic.mjs`, вырезающую эти ограничения только из исходящего запроса. **В любом случае каждый ответ модели заново проверяется локальным AJV** (`server/schema.mjs`, уже существующий путь для Codex/локальной модели) — ослабленная исходящая схема никогда не расширяет то, что приложение фактически примет.
- **Нет точного токенайзера.** В отличие от `local.mjs` (у vLLM есть `/tokenize`), ни один из четырёх облачных вендоров не публикует токенайзер-эндпоинт. Контроль контекста — консервативная оценка по длине текста (заведомо занижающая реальную вместимость), проверяемая до сетевого запроса; текст никогда не обрезается.
- **HTTPS обязателен**, без исключений — в отличие от `local.mjs`, который допускает `http:` для LAN. Проверки SSRF/«только внутренний адрес» из `local.mjs` сюда не перенесены: это осознанно публичные адреса вендоров, а не локальная сеть.
- **Идентичность.** `identityKeys = ['provider','model']` — легче, чем у `LocalRunner` (`+modelRevision/tokenizerRevision/chatTemplateSha256`), так как вендор управляет весами/токенизатором/шаблоном сам.

## Конфигурация

`DOCS_MODEL_PROVIDER=openai|deepseek|kimi|anthropic` (кроме уже существующих `codex`/`local`). Общие для всех четырёх: `DOCS_CLOUD_API_KEY`, `DOCS_CLOUD_MODEL`, `DOCS_CLOUD_CONTEXT_WINDOW`, опционально `DOCS_CLOUD_BASE_URL` (переопределяет вендорский адрес по умолчанию) и `DOCS_CLOUD_API_VERSION` (только Anthropic, по умолчанию `2023-06-01`).
