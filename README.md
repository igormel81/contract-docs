# Договоры и риски — пилот 0.1.1

Назначение: внутреннее рабочее место Кастис / ООО «ЗИС» и ООО «Модеус» на `https://igoruan.ru/docs/`.
Это первая реализация, не весь объём согласованной продуктовой спецификации; проектные материалы хранятся отдельно от репозитория исходников.

## Реализовано

- Самостоятельная регистрация по логину/паролю, серверные сессии, выход, смена пароля; аккаунты изолированы.
- Заказчики, договоры и шаблоны; два независимых профиля подрядчиков.
- Пакетная загрузка PDF/DOC/DOCX по кнопке и перетаскиванием; SHA-256 точных исходников, подсказка похожего текста, подтверждение состава и родителя редакции.
- Сохранение оригиналов и неизменяемых комплектов; просмотр извлечённого текста и скачивание исходников.
- Паспорт и рекомендации: два отдельных запуска `codex exec`, разные инструкции, JSON Schema и проверка цитат на сервере. Первый результат не считается прошедшим ревью.
- Один общий вход Codex через официальный device-auth для приложения; API-ключей нет. Подключение настраивает владелец, все пользователи используют общую очередь и лимит. Авторизация root, других приложений и прежние личные авторизации не используются.
- История запусков, сохранение первичного результата при сбое ревью; новая попытка не затирает старую.
- Редактирование и принятие рекомендаций в план правок, JSON-экспорт.
- Постоянные риски, ответственные, мероприятия, статусы с основанием, сигналы и подтверждение инцидентов; автоматического закрытия рисков нет.
- Просмотр двух редакций рядом, подтверждение действующего комплекта, журнал действий.

## Ограничения пилота

- OCR и проверенная обновляемая нормативная база **не подключены**. Правовые выводы требуют проверки юристом; LAW-01 должен оставаться «нужны данные».
- PDF читается по текстовому слою. DOC — antiword; DOCX — ограниченный разбор XML. Изображения, сложная разметка и исправления требуют проверки оригинала. Оригиналы не преобразуются и не удаляются.
- До 20 МБ на файл, 200 МБ на пользователя, 2 ГБ суммарно; не более 50 файлов в комплекте, 360 000 символов на анализ. Превышения блокируются, текст не обрезается.
- Нет общего доступа сотрудников и полной матрицы ролей. Новый аккаунт видит только собственные данные, анализ использует общее подключение Codex. Единственное специальное право владельца — управление этим подключением.
- Нет автоматического определения заказчика/предмета до анализа, смыслового diff, Word redline, автоматического сопоставления рисков между редакциями, ручных уточнений паспорта и оценки финансовых потерь.
- Подключение шаблона как эталона конкретного анализа, утверждение правил/шаблонов, отчёт разногласий DOCX и полноценная карта обязательств — следующие этапы.
- Файлы и очередь, уже переданные на сервер, сохраняются; выбранные, но ещё не загруженные локальные файлы при перезагрузке страницы теряются. Повторная отправка безопасна благодаря хешу.
- Обработка Codex последовательная. При лимите или ошибке требуется явный повтор. Успешное сохранение авторизации не доказывает доступность модели или наличие лимита.
- Без браузерного подтверждения входа в ChatGPT полноценный AI-сценарий не может быть проверен. Mock-тесты не заменяют проверку реального анализа.

## Среда и запуск

Node.js 22.13+ со встроенным SQLite; AJV 8.20.0. На Linux нужны Python 3, poppler-utils, antiword, bubblewrap. На VPS используется уже установленный Codex CLI 0.152.1.

```sh
npm ci --ignore-scripts
npm run check
npm test
npm start
```

По умолчанию приложение слушает только `127.0.0.1:3107`. Настройки: `DOCS_ORIGIN`, `DOCS_DATA`, `DOCS_PORT`, `DOCS_CODEX`. Изоляция извлечения включена по умолчанию. Только для локального HTTP-теста можно указать `DOCS_EXTRACT_SANDBOX=off`; HTTPS с этим параметром запрещён.

## Общее подключение Codex

`DOCS_CODEX_ADMIN` — точный логин владельца приложения (после нормализации регистра). На текущем VPS в unit-файле задан `igor`, существующий аккаунт владельца. При другой установке измените это значение на контролируемый вами логин. Если параметр не задан, никто не получает право управления авторизацией автоматически, в том числе первый зарегистрировавшийся пользователь.

Владелец открывает настройки → «Подключить общий Codex» и подтверждает вход в ChatGPT. Одноразовый код и действия подключения/отключения доступны только владельцу; сервер проверяет права независимо от интерфейса. Остальные пользователи видят только общий статус. Вход хранится в `$DOCS_DATA/codex/application/auth.json`, вне исходников, в закрытой папке службы; он переживает перезапуск, выход пользователей из приложения и смену их паролей. Каждый анализ по-прежнему состоит из двух независимых сессий с разными инструкциями; общее подключение не объединяет документы и результаты разных пользователей.

Отключение требует подтверждения, останавливает исполняемый анализ и отменяет очередь всех пользователей, затем удаляет только общий локальный файл авторизации. Готовые и уже сохранённые первичные результаты остаются. Повторное подключение не возобновляет отменённые задания автоматически. Это локальное отключение сервиса, не отзыв всех сессий аккаунта ChatGPT.

При обновлении 0.1.0 → 0.1.1 личные каталоги `$DOCS_DATA/codex/<user-id>` не переносятся и не удаляются; новая версия их не использует. Нужен отдельный подтверждённый вход для приложения. Миграция таблиц и изменение пользовательских паролей не нужны.

Регистрация пока открыта: каждый зарегистрированный пользователь может запускать анализ через общий подключённый аккаунт в пределах ограничений сервиса. Для использования вне доверенной команды требуется отдельное ограничение регистрации/доступа. Проверьте пригодность выбранного плана ChatGPT для вашего внутреннего сценария; сохранённый вход не гарантирует квоту или доступность модели.

## Безопасность и размещение

Служба работает как отдельный пользователь `contract-docs`, не root. Исходники доступны только на чтение. БД и оригиналы находятся в `/var/lib/contract-docs`, доступ 0700. Пароли хешируются scrypt; cookie HttpOnly/SameSite/HTTPS, проверка Origin и специального заголовка для изменений, ограничения частоты. Произвольные пути файлов и внешние URL сервер не принимает.

Извлечение документов выполняется в bubblewrap без сети, с одним исходником и ограничением времени/вывода. Codex получает текст через stdin и отдельную папку каждой сессии; только хранилище авторизации общее для приложения. Shell, браузер, приложения, плагины, hooks и другие инструменты отключены. Сервис не наследует API-ключи из окружения. Сохранённый результат не может напрямую менять БД, состояние рисков или исходники.

Публичный маршрут добавляется только для `igoruan.ru` и `/docs` / `/docs/*`. Главный CV-сайт, `/vector`, webhook, HAProxy и VPN-конфигурация сохраняются. `deploy/route.py` сначала проверяет кандидат Caddy, делает закрытую резервную копию и применяет конфигурацию сигналом SIGUSR1 без перезапуска процесса. Не запускать повторно без осмотра.

Перед публикацией: установить пакеты извлечения, развернуть отдельный release, запустить службу, проверить локально вход/загрузку/права, затем добавить маршрут. Для отката маршрута восстановить сохранённый Caddyfile на VPS и отправить SIGUSR1. Данные приложения при откате не удалять.

Для резервного копирования данных использовать SQLite backup API / согласованный снимок БД вместе с файлами. Авторизации Codex содержат секреты: не включать в незашифрованные переносимые архивы. Автоматический внешний backup и политика хранения ещё не настроены; до реальных договоров согласовать их.

## Проверенные источники интеграции

- [Codex authentication](https://learn.chatgpt.com/docs/auth): device-auth, файловое хранилище в CODEX_HOME, защита auth.json. Общая область подключения и права владельца реализованы нашим приложением.
- [Codex non-interactive mode](https://learn.chatgpt.com/docs/non-interactive-mode): `codex exec`, отдельные сессии, JSON Schema, ChatGPT-managed auth.
- [Caddy CLI / Signals](https://caddyserver.com/docs/command-line#signals): SIGUSR1 для `caddy run` с конфигурационным файлом.

## Визуальное направление

Спокойное светлое рабочее место для чтения документов в офисе. Product register / Minimalist: две нейтральные поверхности, зелёный акцент только на действиях и состояниях, системный шрифт, тонкие разделители, без декоративных изображений. Плотность 7/10, вариативность 2/10, движение 1/10. Ориентиры: привычная боковая навигация Linear, документ в центре как в Notion, адресные действия у замечаний. Дизайн-навыки использованы для иерархии и последовательного раскрытия деталей, не для выбора маркетингового шаблона.
